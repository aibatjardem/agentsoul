## Soul-комплект проекта (на базе AgentSoul)

Этот каталог — **«душа» проекта**: свод правил, идентичности и контрактов, на которых выстроена работа Claude Code в этом репозитории. Файлы soul **всегда загружаются** в контекст главного агента через `CLAUDE.md`.

> Если ты новый человек (или новая сессия Claude) и впервые открыл проект — **начни с этого файла**.

---

### Файлы этого каталога

| Файл | Что это | Кто владеет |
|---|---|---|
| `identity.md` | Личность и голос агента, красные линии, иерархия правил | AgentSoul (обновляется через `agentsoul update`) |
| `agents.md` | Карта слоёв, skills и субагентов, правила вызова | AgentSoul |
| `README.md` | Этот файл | AgentSoul |
| `stack.md` | Технологический стек проекта | Проект. Заполняется skill `project-initializer` |
| `glossary.md` | Ubiquitous Language: bounded contexts и термины | Проект. Заполняется skill `glossary-initializer` |
| `config.json` | Профиль и модели субагентов | Проект |
| `local/*.md` | **Локальные правила проекта.** Самый сильный слой | Проект |
| `.agentsoul.json` | Манифест: версия AgentSoul, профиль, хеши управляемых файлов | CLI (не трогай) |

Файлы с владельцем «AgentSoul» руками **не правят**: локальная правка помечается как drift, а при обновлении новая версия ляжет рядом как `*.agentsoul-new`. Хочешь своё правило — положи его в `local/`.

---

### С чего начать (новая сессия / новый проект)

1. Прочитай `identity.md` — базовая личность и иерархия правил.
2. Прочитай `local/*.md` — что в этом проекте устроено иначе.
3. Прочитай `agents.md` — карта skills и субагентов.
4. `stack.md` содержит `TBD` → запусти skill `project-initializer` (в Claude Code: `/project-initializer`).
5. `glossary.md` содержит `TBD` → запусти skill `glossary-initializer`. Сначала стек, потом язык.

Агенты, работающие на незаполненном baseline, дают абстрактные советы, которые могут противоречить реальному стеку и языку команды. Поэтому субагенты в таком состоянии останавливаются и просят инициализацию — это дизайн, а не поломка.

---

### Три слоя

- **Soul** (`.soul/`) — всегда в контексте. Лёгкий: личность, карта, стек, язык, локальные правила.
- **Skills** (`.claude/skills/`) — знания и диалоги, загружаются в контекст по требованию. Справочные гайды (`architecture-guide`, `conventions-guide`, `infrastructure-guide`, `stack-reference`) и опросники первичной настройки (`project-initializer`, `glossary-initializer`).
- **Субагенты** (`.claude/agents/`) — исполнители с изолированным контекстом, узкими правами и явной моделью. Нужные справочные skills им подгружаются при старте.

Подробности — в `agents.md`.

---

### Как поддерживать

| Хочу | Делай |
|---|---|
| Своё правило только для этого проекта | Новый файл в `.soul/local/`, затем `npx agentsoul update` (подключит его в `CLAUDE.md`) |
| Другая модель для субагентов | `.soul/config.json` → `models`, затем `npx agentsoul update` |
| Обновить AgentSoul | `npm update @aibatjardem/agentsoul && npx agentsoul update --dry-run`, потом без `--dry-run` |
| Добавить / удалить / переименовать агента или skill | Субагент `soul-keeper` |
| Проверить, что ничего не разъехалось | `npx agentsoul check` |
| Сменить стек или расширить домен | Skill `project-initializer` / `glossary-initializer` |

---

### Скорая помощь

| Проблема | Решение |
|---|---|
| `stack.md` пуст, агенты останавливаются | Skill `project-initializer` |
| Субагент или skill не найден | Перезапусти Claude Code — они обнаруживаются при старте сессии |
| После `update` появились `*.agentsoul-new` | Ты правил управляемый файл. Слей правки (через `soul-keeper`), перенеси проектное в `local/`, удали `.agentsoul-new`, повтори `update` |
| `check` показывает drift | То же: управляемый файл изменён локально |
| Глобальное и локальное правило конфликтуют | `local/` > `.soul/*` и skills > глобальные defaults. См. `identity.md` |
