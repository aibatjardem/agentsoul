## ⚠ Session bootstrap — прочитать ПЕРВЫМ

**Перед выполнением любой нетривиальной задачи** проверь состояние baseline-файлов проекта:

1. Если `.soul/stack.md` содержит `TBD` / "ещё не заполнен" / пустые обязательные разделы → предложи пользователю запустить субагента **`project-initializer`** и дождись его завершения, **прежде чем** начинать писать код или архитектуру.
2. Если `.soul/glossary.md` содержит `TBD` / "ещё не заполнен" → предложи субагента **`glossary-initializer`**. Без Ubiquitous Language любая работа с доменом будет рассинхронизирована с командой.

**Исключения из правила** — можно работать даже если baseline пуст:
- Тривиальные правки одного файла, не затрагивающие архитектуру/домен (переименование, форматирование, очевидные bug fix)
- Исследовательские запросы ("где живёт X?", "как работает Y?")
- Пользователь явно говорит "я знаю что baseline пуст, делай быстро"

Во всех остальных случаях — **сначала инициализация, потом работа**. Иначе советы будут абстрактны и разойдутся с реальностью проекта.

## ⚠ Особый режим: этот проект — AgentSoul (dogfood)

**Это не обычный консьюмер soul-комплекта. Это сам soul-комплект.**

Файлы в `.soul/` и `.claude/agents/` этого репозитория — **зеркало `core/`**. Источник истины — `core/`. Если ты правишь soul-файл здесь, обязан синхронизировать с `core/` (или сначала править в `core/` и потом зеркалить).

Правила для работы в этом репо:

1. **Не редактируй `.soul/identity.md`, `.soul/agents.md`, `.soul/README.md` или `.claude/agents/*` напрямую** — правь сначала `core/soul/*` или `core/claude-agents/*`, потом синхронизируй.
2. **`.soul/stack.md` и `.soul/glossary.md`** — это **реальные файлы AgentSoul'а для себя**, не шаблоны. Заполняются обычным `project-initializer` / `glossary-initializer` для описания технологий и домена самого AgentSoul.
3. **`core/soul/stack.md` и `core/soul/glossary.md`** — это **шаблоны-placeholder'ы**, которые копируются в проекты-консьюмеры при `agentsoul init`. Их содержимое — "ещё не заполнен / TBD", и они НЕ должны содержать реальных данных.
4. При любом изменении — обязательно `npm run check` + `bash scripts/check-soul.sh`.
5. Для структурных изменений (добавить/удалить/переименовать субагента) — вызывай `soul-keeper`.

Полный индекс субагентов — в `.soul/agents.md`.
