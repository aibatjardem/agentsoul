## Soul-комплект проекта (на базе AgentSoul)

Этот каталог — **"душа" проекта**. Не код, не документация в обычном смысле, а свод правил, идентичности и контрактов, на которых выстроена вся работа Claude Code в этом репозитории. Всё, что здесь лежит, **всегда загружается** в контекст главного агента через `CLAUDE.md`.

> Если ты новый человек (или новая сессия Claude) и впервые открыл проект — **начни с этого файла**, он за 5 минут объяснит, что и где.

---

### Файлы этого каталога

| Файл | Что это | Источник правды |
|---|---|---|
| `identity.md` | Личность и голос агента. Как общается, что любит, чего не терпит, красные линии. | Пишется вручную. Меняется редко. |
| `agents.md` | Индекс субагентов и правила их вызова. Иерархия правил (локальное > глобальное). | Пишется вручную, обновляется через `soul-keeper` при изменении состава субагентов. |
| `stack.md` | Конкретный технологический стек проекта. Заполняется **автоматически** через опросник. | `project-initializer` (субагент). **Не правь вручную.** |
| `glossary.md` | Ubiquitous Language проекта. Bounded Contexts + каноны доменных терминов. | `glossary-initializer` (субагент). **Не правь вручную.** |
| `README.md` | Этот файл. | Пишется вручную. |

---

### С чего начать (новая сессия / новый проект)

1. **Прочитай `identity.md`** — это базовая личность, без неё общение будет не в тон.
2. **Прочитай `agents.md`** — это карта территории, здесь 25+ субагентов и правила их вызова.
3. **Проверь `stack.md`** — если там `TBD` / "ещё не заполнен", запусти субагента `project-initializer`:
   ```
   Agent({ subagent_type: "project-initializer", prompt: "Инициализируй проект" })
   ```
4. **Проверь `glossary.md`** — если пусто, запусти `glossary-initializer` после `project-initializer` (сначала стек, потом язык).
5. **Только после заполнения обоих** — приступай к задачам.

Это не бюрократия, это — прогрузка контекста. Агенты, работающие на незаполненном baseline, дают абстрактные советы, которые могут противоречить реальному стеку и языку команды.

### Как работают субагенты

Subagent в Claude Code — это **отдельный Claude-инстанс** с собственным system prompt'ом, который вызывается через `Agent` tool и возвращает текстовый ответ. Он не имеет доступа к контексту главного агента, поэтому:

- При вызове субагента **передавай релевантный контекст в промпте** (фрагменты `stack.md`, `glossary.md`, затронутые файлы).
- Субагент сам прочитает `.soul/stack.md` и `.soul/glossary.md` в начале работы (это прописано в его system prompt).
- Если baseline не заполнен — субагент **остановится** и попросит тебя запустить инициализатор. Не паникуй, это дизайн.

Два типа субагентов:

- **Executor** — делает работу (проектирует, ревьюит, отлаживает, рефакторит). Живёт в `.claude/agents/`.
- **Knowledge-guide** — отвечает на архитектурные вопросы, загружая в ответ философию (Clean Architecture, Conventions, Infrastructure). Тоже в `.claude/agents/`, но используется как консультант, не как исполнитель.
- **Initializer** — интерактивно заполняет baseline-файлы (`project-initializer`, `glossary-initializer`).
- **Meta** — `soul-keeper`, отвечает за консистентность самого soul-комплекта.

Подробности — в `agents.md`.

### Как поддерживать soul-комплект

Не правь файлы soul'а хаотично. Правила простые:

- **Меняешь философию / правила / идентичность** → обсуди с пользователем → правь файл → прогони `bash scripts/check-soul.sh`.
- **Добавляешь / удаляешь / переименовываешь субагента** → вызови `soul-keeper`, он проведёт изменение через все затронутые файлы атомарно.
- **Переинициализируешь стек или глоссарий** → запусти соответствующий `*-initializer`. Не редактируй `stack.md` / `glossary.md` вручную.
- **Перед коммитом в soul** → прогони `bash scripts/check-soul.sh` и убедись, что errors: 0, warnings: 0.

Скрипт валидации (`scripts/check-soul.sh`) проверяет:
- YAML frontmatter всех субагентов валиден
- `name:` в frontmatter совпадает с именем файла
- Индекс `agents.md` упоминает все существующие файлы агентов
- Все упомянутые агенты существуют (нет битых ссылок)
- Все `@import` в `CLAUDE.md` указывают на существующие файлы

### Философия

Soul-комплект — это **инвестиция, не overhead**. Да, baseline занимает ~500 строк контекста. Да, инициализация нового проекта требует 15-30 минут опросника. Но:

- После инициализации каждая последующая задача получает правильный технический и доменный контекст **бесплатно** — не нужно в промпте каждый раз повторять "мы используем X, наш домен — Y".
- Агенты не противоречат друг другу, потому что все читают один baseline.
- Новый член команды (или новая сессия) входит в проект за 5 минут через этот README, а не за день погружения.
- Правила закреплены как код — их можно версионировать, ревьюить, откатывать.

Если soul-комплект мешает — это сигнал, что он устарел или слишком жёсткий, а не то, что сама идея плоха. Правь через `soul-keeper`, не обходи.

### Скорая помощь

| Проблема | Решение |
|---|---|
| `stack.md` пуст, ничего не работает | `Agent({ subagent_type: "project-initializer", ... })` |
| Не помню, какой субагент для чего | См. таблицы в `.soul/agents.md` |
| Subagent не найден | Перезапусти Claude Code — список обнаруживается при старте сессии |
| Что-то разъехалось в soul | `bash scripts/check-soul.sh` → исправь по отчёту (или через `soul-keeper`) |
| Глобальный и локальный правила конфликтуют | Локальное (`.soul/*`) побеждает всегда, см. `identity.md` раздел "Иерархия правил" |
