# AgentSoul 0.3 — плагин, мультиязычность, два языка интерфейса

Дата: 2026-11-21. Статус: одобрен владельцем 2026-11-21. Английская версия (`agentsoul-en`) отложена: строятся этапы 1 (плагин `agentsoul-ru`) и 2 (языковые пакеты); структура `src/locales/` сохраняет место под `en`.

## Зачем

Комплект передаётся другим людям — русскоязычным новичкам, которые с Claude Code будут писать сайты и ботов. Инструмент остаётся **серьёзным**: архитектурная дисциплина, строгость, специалисты — это ценность, а не помеха. Убрать нужно три вещи, которые мешают им пользоваться:

1. **Жёсткая привязка к TypeScript.** Правила, опросник, профили и часть текстов агентов предполагают TS/Node. Человек с ботом на Python получает чужие советы.
2. **Установка через npm.** Claude Code ставится официальным установщиком без Node.js; у Python-разработчика Node может не быть вовсе.
3. **Только русский язык.** Нужен и английский.

Успех: новичок ставит плагин двумя командами в Claude Code, запускает `/agentsoul-ru:setup` в своём проекте, отвечает на вопросы, и дальше агенты дают советы про **его** язык и стек — не про TypeScript.

## Цели

- Работа на **TypeScript, Python, Go, Java, C#** «из коробки»; набор языков расширяется добавлением пакета по шаблону.
- Архитектура, философия и общие правила кода — **без языка**. Языковое — только в языковых пакетах.
- Распространение **плагином Claude Code** через маркетплейс в репозитории `aibatjardem/agentsoul`; ни Node, ни npm у пользователя не нужны.
- Полные **русская и английская** версии с одинаковым составом; расхождение ловит CI.

## Не-цели

- Не делаем комплект «мягче»: красные линии, Clean Architecture/DDD, тесты остаются.
- Не поддерживаем каждый язык одинаково глубоко с первого дня — пять пакетов одного уровня, остальные по запросу.
- Не делаем GUI/веб-настройщик.
- Не сохраняем npm-установку для пользователей (см. «Миграция»).

## Анти-цели (провал, даже если «работает»)

- Python-разработчик видит в советах `any`, `tsc`, `npm`, Prisma.
- Английская версия тихо отстаёт от русской.
- Новичок не понимает, что делать после установки.
- Хук при старте ломает сессию или замедляет её (ошибка в хуке, огромный контекст).

## Решения (приняты с владельцем)

| Вопрос | Решение |
|---|---|
| Аудитория | новички, сайты и боты; инструмент остаётся серьёзным |
| Языки программирования | TypeScript, Python, C#, Java — названы владельцем; плюс Go (решение исполнителя: часто пишется Claude) |
| Язык текстов | русский основной, английский — полная копия |
| Распространение | плагин Claude Code |

## Устройство

### Репозиторий

```
aibatjardem/agentsoul
├── .claude-plugin/marketplace.json     маркетплейс: два плагина
├── src/                                 исходники комплекта (единый источник истины)
│   ├── shared/                          не зависит от языка интерфейса: hooks, скрипты
│   └── locales/{ru,en}/
│       ├── soul/                        identity.md, agents.md, bootstrap.md
│       ├── skills/<name>/SKILL.md       гайды, опросники, setup, языковые пакеты
│       ├── agents/<name>.md             19 исполнителей
│       ├── templates/                   шаблоны stack.md, glossary.md, local/rules.md
│       └── profiles/<name>/             заполненные шаблоны стека
├── plugins/agentsoul-ru/ , plugins/agentsoul-en/   СОБРАННЫЕ плагины (генерируются, коммитятся)
└── tools/                               сборщик и валидатор на TypeScript (только для разработки)
```

Плагины в `plugins/` собираются из `src/` командой `npm run build:plugins` и коммитятся — маркетплейс читает их прямо из git. CI проверяет, что собранное совпадает с исходниками (иначе — ошибка «забыли пересобрать»).

### Три слоя внутри плагина

| Слой | Как попадает в контекст |
|---|---|
| **Soul** — личность, иерархия правил, карта агентов | хук `SessionStart` плагина: сжатое ядро в каждой сессии; полный текст — skill `{{plugin}}:soul` |
| **Skills** — справочные гайды, языковые пакеты, опросники, setup | по требованию (главный агент вызывает; субагенты получают через `skills:`) |
| **Субагенты** — 19 исполнителей | изолированный процесс, как сейчас |

Данные проекта живут в самом проекте: `.soul/stack.md`, `.soul/glossary.md`, `.soul/local/*.md`. Хук при старте сообщает о них главному агенту (пути, языки, локальные правила — см. «Хук при старте сессии») или подсказывает запустить `setup`, если их нет.

### Язык программирования

- **`conventions-guide`** становится языконезависимым: нейминг, явная обработка ошибок вместо исключений-сюрпризов, никаких заглушек и мёртвого кода, комментарии «почему», тест рядом с поведением, строгая типизация как принцип.
- **Языковые пакеты** — отдельные skills `lang-typescript`, `lang-python`, `lang-go`, `lang-java`, `lang-csharp`. В каждом одинаковые разделы:
  1. строгость типов и инструменты (TS strict / mypy strict + type hints / go vet + staticcheck / javac -Xlint + nullness / nullable reference types);
  2. линтер и форматтер;
  3. тесты (Vitest / pytest / go test / JUnit 5 / xUnit);
  4. структура проекта и как в ней выглядят слои Clean Architecture;
  5. как на этом языке выражаются порты, Result/ошибки, value objects, DI;
  6. типичные ошибки новичка и красные линии языка (`any`, `# type: ignore`, игнор `err`, `null` без проверки…).
- **`.soul/stack.md`** получает обязательное поле «Языки» (один или несколько). Языковые пакеты подгружаются по нему: главный агент загружает нужный `lang-*`, субагенты получают в `skills:` общие гайды и инструкцию «прочитай `.soul/stack.md` и следуй пакету своего языка».
- **`identity.md`**: «Не использую `any`» → «Не отключаю проверку типов и линтер ради скорости» — конкретика в пакете языка.
- **Профили** стека пересобираются под языки: `blank`, `ts-nextjs` (сайт), `ts-node-api`, `python-fastapi`, `python-bot` (aiogram), `go-api`, `java-spring`, `csharp-aspnet`. Набор — решение исполнителя, легко меняется.
- **`project-initializer`** первым вопросом спрашивает язык(и), дальше предлагает варианты под выбранный язык.

### Язык интерфейса

- Два плагина: `agentsoul-ru`, `agentsoul-en`. Пользователь ставит один.
- Тексты агентов и skills — на языке плагина; агенты отвечают пользователю на нём же.
- Поле `description` агентов и skills — **на английском в обоих плагинах** (по нему Claude выбирает специалиста). Решение исполнителя.
- Валидатор требует одинаковый набор агентов, skills, профилей и разделов языковых пакетов в обеих локалях.

### Новичок: путь от нуля

1. `/plugin marketplace add aibatjardem/agentsoul`
2. `/plugin install agentsoul-ru@agentsoul`
3. В проекте: `/agentsoul-ru:setup` — спрашивает: новый проект или существующий; язык(и); профиль или опросник; домен. Создаёт `.soul/` и добавляет `.soul/` в git (не в `.gitignore`).
4. Дальше работа как обычно; при старте сессии хук сообщает, что soul загружен и какой стек у проекта.

README — пошаговый для новичка, на двух языках.

## Факты платформы

Проверено по документации code.claude.com 2026-11-21 (страницы sub-agents, plugins/components, plugins/manifest-reference, hooks, plugin-marketplaces, plugins/loading).

| Факт | Следствие для дизайна |
|---|---|
| `additionalContext` хука SessionStart — жёсткий лимит **10 000 символов**; сверх — Claude получает только путь к файлу и первые 2 000 символов | Хук отдаёт **сжатую душу**; полный текст — в skill. Бюджет проверяется валидатором (см. «Хук») |
| Агенты плагина имеют id `<плагин>:<имя>` (`agentsoul-ru:code-reviewer`); skills вызываются `/<плагин>:<skill>` | Все упоминания агентов и skills в текстах — с префиксом; сборщик подставляет префикс своей локали (`{{plugin}}:`) |
| В агентах плагина игнорируются `permissionMode`, `hooks`, `mcpServers`, `initialPrompt`; `name`, `description`, `tools`, `model`, `skills`, `color` и др. работают | Используем только `name`, `description`, `tools`, `model`, `skills`; валидатор запрещает игнорируемые поля. Ссылки на агентов (`subagent_type`) — с префиксом плагина |
| `skills:` в агенте — реальное поле: содержимое skill вставляется при старте агента (до 32 имён); отсутствующий skill пропускается **молча** (только в debug-логе) | Главный риск: **как писать имя плагинного skill в `skills:` — голым или с префиксом — документация не говорит**. Первый шаг реализации — живая проверка (см. «Риски») |
| `model`: `sonnet`, `opus`, `haiku`, `fable`, `inherit`, полный id | Без изменений |
| Одноимённый агент проекта (`.claude/agents/foo.md`) приоритетнее плагинного, но id плагинного — `agentsoul-ru:foo`, коллизии нет | Плагин не перекрывает агентов пользователя и наоборот |
| Хук: `${CLAUDE_PLUGIN_ROOT}`, `CLAUDE_PROJECT_DIR`; рабочая директория — текущая директория сессии, не обязательно корень проекта | Хук ищет `.soul/` в `CLAUDE_PROJECT_DIR`; на Windows запуск через обёртку `run-hook.cmd` (как в superpowers) |
| Матчеры SessionStart: `startup`, `resume`, `clear`, `compact`, `fork` | Подключаем на `startup|clear|compact` — после сжатия контекста душа возвращается |
| Обновления: автообновление для сторонних маркетплейсов **выключено по умолчанию**; версия берётся из `plugin.json`, и пока строка не изменится, пользователи остаются на кэше | Версия поднимается при каждом релизе (сборщик пишет одну версию в оба `plugin.json`, в `marketplace.json` версию не дублируем). README учит включить автообновление: `/plugin` → Marketplaces |
| `claude plugin validate .` проверяет маркетплейс и плагины | Входит в CI, если CLI доступен в раннере; иначе — в ручной чек-лист релиза |

### Хук при старте сессии

Хук собирает контекст из двух частей и укладывается в бюджет **≤ 9 000 символов** (запас до лимита 10 000):

1. **Статическое ядро ≤ 6 500 символов** — сжатая душа: кто я, красные линии, иерархия правил, «как спрашивать», карта (одна строка на агента/skill с полным id) и правило старта. Полные `identity` и карта — в skill `{{plugin}}:soul`, их можно загрузить целиком.
2. **Состояние проекта** — динамически:
   - `.soul/` нет → одна строка: «в этом проекте soul не настроен, предложи `/{{plugin}}:setup`»;
   - `.soul/` есть → пути к `stack.md`, `glossary.md`, `local/*.md`, языки из `stack.md` (строка «Языки») и указание прочитать эти файлы перед нетривиальной задачей и загрузить `{{plugin}}:lang-<язык>`. Содержимое `local/*.md` вставляется целиком, если влезает в остаток бюджета; иначе — путь и пометка «прочитай обязательно».

Хук — bash-скрипт без внешних утилит (только встроенные средства bash, как в superpowers), всегда завершается кодом 0 и выдаёт валидный JSON; при любой ошибке — короткое сообщение вместо контекста, сессию не ломает.

## Решения исполнителя (по итогам рецензии)

Помечены как решения исполнителя — владелец может пересмотреть любое.

1. **Модели агентов.** У всех 19 агентов `model: inherit` — работают на модели сессии пользователя. Причина: для новичков на недорогих тарифах фиксированный `opus` у каждого агента — неожиданный расход лимита. Настройка моделей по проекту (`config.json` из 0.2) **убирается** — плагин не может переписывать frontmatter под проект. Кому нужна другая модель — документированный способ: свой агент в `~/.claude/agents/` или выбор модели при вызове.
2. **Как субагент получает языковой пакет.** Всем агентам добавляется инструмент `Skill` (он только загружает текст, прав на запись не даёт — принцип RO/RW сохраняется). Первое действие агента по шаблону: прочитать строку «Языки» в `.soul/stack.md` и загрузить `{{plugin}}:lang-<язык>`. Общие гайды по-прежнему в `skills:`. Этот же механизм — запасной путь из риска 1.
3. **Миграция с 0.1/0.2 — без хешей.** Таблица хешей 0.1 и манифест больше не используются. Skill `setup` находит старую установку по признакам (`.soul/.agentsoul.json`, `.soul/identity.md`, блок `agentsoul:begin` в `CLAUDE.md`, агенты комплекта в `.claude/agents/`), **показывает полный список** того, что удалит, и удаляет только после подтверждения. Сохраняет: `stack.md`, `glossary.md`, `local/`, `.backup/`. Удаляет: `.soul/identity.md`, `agents.md`, `README.md`, `config.json`, `.agentsoul.json`, копии агентов и skills комплекта, блок в `CLAUDE.md`. Если пользователь правил агента — его правки он увидит в списке и сможет перенести в `local/`.
4. **Сам репозиторий.** Самоустановка (dogfood) прекращается: корневые `.claude/agents`, `.claude/skills`, `.soul/identity.md`, `agents.md`, `README.md`, манифест удаляются. В `.soul/` остаются реальные `stack.md`/`glossary.md` проекта (переписанные под новое устройство) и `local/dogfood.md` с правилами разработки комплекта. Для работы над комплектом разработчик ставит `plugins/agentsoul-ru` из локального маркетплейса (`/plugin marketplace add ./`). CI вместо проверки самоустановки проверяет, что собранные плагины совпадают с исходниками.
5. **`soul-keeper`.** Остаётся, роль меняется: хранитель `.soul/` проекта — согласованность `stack.md`, `glossary.md`, `local/` между собой и с кодом, помощь в миграции со старых версий, перенос правил в `local/`. Агентов по-прежнему 19.
6. **Паритет ru/en по содержанию.** Каждый английский файл хранит во frontmatter-комментарии хеш русского исходника, с которого переведён (`source-sha`). CI падает, если русский файл изменился, а хеш в английском — нет: «переведи заново». Структурный паритет (состав агентов, skills, профилей, разделов пакетов) проверяется отдельно.

## Риски

1. **Имя skill в `skills:` у плагинного агента — СНЯТ (спайк 2026-11-21, Claude Code 2.1.330).** Минимальный плагин, `claude -p --plugin-dir`: работают обе формы — голое имя и `плагин:имя`; хук `SessionStart` доставляет `additionalContext` главному агенту. Решение: в `skills:` пишем `{{plugin}}:<имя>` — однозначно и не сталкивается с одноимённым skill пользователя.
2. **Бюджет хука.** Сжатая душа теряет нюансы полной. Смягчение: skill `{{plugin}}:soul` с полным текстом, и правило в ядре «при спорной ситуации загрузи soul целиком».
3. **Windows.** Хук на bash требует Git for Windows; обёртка `run-hook.cmd` ищет bash и при отсутствии молча выходит — тогда душа не грузится, но сессия работает. README говорит об этом.

## Миграция

- **С 0.1 и 0.2:** делает skill `setup` — см. «Решения исполнителя», п. 3 (без хешей, полный список и подтверждение перед удалением).
- **npm-пакет** больше не публикуется для пользователей; инструменты в `tools/` нужны только для разработки. Workflow публикации в npm удаляется.

## Проверка качества

- `tools/` валидатор: frontmatter агентов и skills, ссылки `skills:`, индекс в `agents.md`, паритет ru/en, одинаковые разделы во всех языковых пакетах, собранные плагины совпадают с исходниками, хук-скрипт проходит `bash -n`.
- Тесты: сборка плагинов, валидатор (позитивные и негативные), хук — вывод валидного JSON с проектом и без `.soul/`.
- Ручная проверка: установка плагина из локального маркетплейса в чистый проект, `setup`, вызов одного агента и одного языкового пакета.
